# 常见错误与踩坑记录

## G001 拿到需求直接写代码，跳过 plan

- 后果：规格丢失、人无法确认方向、返工
- 正确：至少产出最小 plan 并经人确认；用户豁免除外

## G002 plan 只写步骤不写决策

- 后果：agent 只能照步骤机械执行，遇到 plan 未覆盖的情况无法做正确判断；人无法评估方案
- 正确：plan 必须含"关键决策"（选择了什么、放弃了什么、为什么）

## G003 UI 改动不给预览

- 后果：人无法验收 UI，只能看代码猜效果
- 正确：涉及 UI 的 plan 必须提供设计图或 HTML 交互预览

## G004 完成任务不更新文档

- 后果：文档与代码脱节，下一次任务上下文缺失
- 正确：文档是交付物的一部分；改完代码同步改文档 + INDEX.md

## G005 依赖对话记忆而非文档

- 后果：对话压缩/切换会话后任务规格丢失
- 正确：规格在 docs/issues + docs/plans 里，随时可恢复

## G006 忘记 plan review 和实现 review

- 后果：单视角遗漏（博客原话：独立 review 站在不同视角，能大幅提高准确性和稳定性）
- 正确：plan 和实现各做一次独立 review（fresh context subagent）
