# M2-2 角色运行时接入 pi SDK（plan）

## 任务解释

把 M2-1 的假执行器换成真实模型执行器：用 pi SDK 接 opencode-go 的 `deepseek-v4-flash`，让 Planner 真实生成检索计划并进入审批，跑通“问题 → 计划”第一段真链路；用量落库、失败有状态。

## 关键决策

| 决策点 | 选择 | 放弃 / 备选 | 理由 |
|--------|------|-------------|------|
| pi SDK 版本 | `^0.80.3`（与旧项目同版本） | 最新版 | 旧项目已验证可用且坑已踩过；engines node>=22.19 满足（当前 22.22） |
| Provider 接入 | 优先用 pi 内置 opencode-go；若无内置则 `registerProvider`（baseUrl `https://opencode.ai/zen/go/v1` + Bearer key） | 手写 HTTP 客户端 | 复用 SDK 的鉴权 / 流式 / 用量能力 |
| 默认模型 | `deepseek-v4-flash` | deepseek-chat 等旧名 | opencode-go 目录实测存在（/v1/models 返回 25 个模型） |
| 模型选择机制 | `PI_DEFAULT_MODEL` + `PI_MODEL_<ROLE>` 环境变量覆盖，未设置回退默认 | UI 配置 | MVP 先环境变量，UI 后置 |
| Key 存放 | 环境变量 `OPENCODE_GO_API_KEY`（可选 pi auth.json） | 写进仓库 | 安全；key 绝不入库 |
| 执行器 | `PiStepRunner`：组装角色 prompt + 输入 artifact 摘要 → provider.send → artifact 内容 | 保留 Fake 为测试用 | 可注入、可单测 |
| 失败语义 | 新增 `failed` 状态（workflow / step），runner 异常置 failed 并广播 | 只抛 500 不落状态 | 否则工作流会卡在 running，不可观测 |
| 用量统计 | pi 事件流 → `usage_records` + 广播 `usage.recorded` | 后处理估算 | 成本可见，为 M3 预算上限铺路 |

## 实现步骤

1. `apps/server` 安装 `@earendil-works/pi-coding-agent@^0.80.3`
2. **验证 SDK 内置 opencode-go**：查 pi 的 models.json / ModelRegistry 是否已有 `opencode-go`；没有则用 `registerProvider` 注册（baseUrl + apiKey + deepseek-v4-flash 模型元数据）
3. `src/runtime/piConfig.ts`：解析 `OPENCODE_GO_API_KEY` / `PI_DEFAULT_MODEL` / `PI_MODEL_*`，非法值报配置错误
4. `PiRuntimeProvider`：`createRuntime(role, systemPrompt)` 创建 pi AgentSessionRuntime，注入角色 system prompt（沿用旧项目 `agent.state.systemPrompt` 替换方式）；`send` 聚合输出，`close` 释放
5. `PiStepRunner`：prompt = 角色系统提示 + 输入 artifact 摘要 + “输出 markdown artifact”；调用 provider；返回内容
6. `shared` + engine：状态增加 `failed`；`runPendingSteps` 捕获 runner 异常 → step/workflow 置 failed → 广播
7. usage 映射：pi 事件流中 OpenAI 兼容字段（`prompt_tokens` / `completion_tokens` / `prompt_cache_hit_tokens`）→ `usage_records`，广播 `usage.recorded`
8. `index.ts`：用 PiStepRunner 替换 FakeStepRunner（缺 key 时可启动，调用时返回 503 明确提示）
9. 测试 + 手动验证 + 文档

## 测试方案

- **单测**：piConfig 默认/覆盖/非法值解析；PiStepRunner 用 mock provider 验证 prompt 组装与 artifact 写入；engine 在 runner 抛错时置 failed 并广播
- **手动验证**：配置真实 key 后跑四步工作流，检查 `01-plan.md` 内容（子问题 / 关键词 / 大纲）与 `usage_records` 记录；再删掉 key 验证 503 提示
- **CI**：typecheck + test 全绿（真实调用不进 CI）
