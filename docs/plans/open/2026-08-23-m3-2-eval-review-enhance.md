# M3-2 评估与审查增强（plan）

## 任务摘要
把评估从"模型描述式"升级为可横向比较的六维完整评分制，并给审查加"完整性批评"视角，自动列出该覆盖却未覆盖的方向。

## 为什么做
评估报告目前是模型文字结论（主题匹配/相关度/大纲覆盖/来源失败），缺可比分值；m2-13-effect-audit 建议升级为六维评分。reviewer 单一视角，抓引用/证据类问题，缺"完整性批评"，而这正是答辩最有冲击力的发现（作品知道自己漏了什么）。

## 预计效果
- evaluation-report 含六维每维分值+理由+总分，可横向比较；
- reviewer/评估含"完整性批评"覆盖缺口（≥2 条，每条"缺什么/为什么重要"）；
- 前端评估/审查 tab 可读六维分与覆盖缺口。

## 关键决策
| 决策点 | 选择 | 放弃 | 理由 |
|---|---|---|---|
| 六维 | 模型按提示输出 0-5 分+理由，服务端解析成表 | 纯规则计算 | 六维含"完整性"等需语义判定，模型判更准，规则作对账 |
| 完整性批评 | 并入 evaluator/reviewer 提示的一个固定小节 | 加独立 critic 角色 | 不加角色，避免流程改动；一个模型视角足够 |
| 解析 | 服务端从模型输出提取六维表，落 `evaluation-report.md` | 前端临时解析 | 产物确定性、可测试 |

## Review 发现与修正
- [major] 模型输出格式不稳定 → 修正：给固定表格模板 + 服务端宽容解析（缺失维置"未作答"，不崩）。
- [minor] 六维里"完整性"与"大纲覆盖"语义重叠 → 修正：大纲覆盖=计划章节，完整性=计划之外值得补充的方向。
- [minor] 避免六维全满分 → 修正：提示强调"每维需给出一个不足"，防敷衍。

## 实现步骤
1. `prompts.ts` evaluator 提示：六维表格模板（主题匹配/相关度/大纲覆盖/引用可信/来源失败/完整性）+ 完整性批评小节。
2. `prompts.ts` reviewer 提示：新增"完整性批评"小节（该覆盖未覆盖方向）。
3. 服务端解析器：从模型输出提取六维表与完整性批评，附加/更新 `evaluation-report.md`。
4. web 评估/审查 tab：展示六维分与覆盖缺口。

## 测试与验证
- 单测：六维解析器（含缺失维容错）；完整性批评小节提取；评估/审查 prompt 含新指令。
- 复现：`npm run typecheck && npm test`。

## 验收标准

- [ ] 前端评估/审查可读六维分与缺口
- [ ] typecheck/test 全绿
