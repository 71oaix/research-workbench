# M2-8 内化清单逐项论证

本文回答一个问题：M2-8 清单里的每一项，为什么需要，为什么采用这种具体做法。判断依据只有三类：研镜真实运行暴露的问题、两个参考项目的既有做法、以及 MVP 与竞赛目标的成本收益。

## 总原则

参考项目被证明有效的，不是某个模型提示词，而是“把流程拆成确定性的规范片段，在正确时刻加载，并用脚本强制执行”。研镜现在缺的正是这一层。下面每项都落在“可审查、可复现、可控成本”三条上。

## A. 分层路由架构（manifest + fragments）

为什么需要：真实运行里 planner 写得不错，但 researcher 打回后策略不变、writer 自创 `[V1-x]` 引用格式、reviewer 输出的可执行性也不稳定。根因不是模型能力，而是所有规则都塞在一个静态提示词里，模型在每一步自由决定遵守多少。

为什么这么做：nature-skills 的“短 router + manifest + 按需 fragment”明确要求“从磁盘加载，不凭记忆执行”。好处有三点：片段可版本化、可独立审查；运行到哪一步只加载哪一段，避免提示词越长越互相污染；加一个新工作流只加一个片段。它同时是 B 到 I 的承载层，所以先做骨架，而不是每个功能各自写死提示词。

成本：需要一套“规范片段 + manifest + 运行时加载”的轻机制（放在 docs 或代码常量里即可），中等成本，但收益覆盖后面所有项。

## B. 检索规范（源分级 / 查询构造 / 去重 / 限流）

为什么需要：真实运行中 Semantic Scholar 三组全失败、OpenAlex 中文查询严重漂移、打回后结果不升反降，还出现过同一篇论文多个 DOI 版本没合并。这些都不是偶发，是缺少确定性检索策略。

为什么这么做：

- 源分级 T1→T2→T3：把“可靠性”显式编码，区分 API 源与抓取源，失败时按档位兜底，而不是双源一起烂。nature-skills 的 domain→tier 映射直接可借鉴。
- 查询构造：概念→同义词→布尔查询，加数量阈值（>500 收窄、<10 放宽）。这是零模型成本的确定性反馈，能直接改善“打回后还是那一批关键词”的问题。
- 去重引擎：DOI 主键 + 标题/首作者 Jaccard≥0.90 兜底。我们现在的 any-key 标题合并已经修了 PRISMA 多版本问题，但还没有 DOI 之外的稳健兜底，作者兜底能再降误合并。
- 限流与 ToS：把 rate limit 封进客户端脚本，禁止 agent 自己发请求，429 退避并回传错误体。science-skills 的 38 个 skill 都这么做，是稳定性基线。

成本：M2-7 已覆盖大部分（源、补偿、去重、限流），M2-8 只是把它升级为可加载的规范；MVP 必做。

## C. 引用核验（字段级多源交叉）

为什么需要：我们现在的 lint 只判断“编号在不在卡片范围”，真实运行里 writer 用 `[V1-x]` 后 lint 报 0，而且完全没有验证“这篇论文是否真的支持这句话”。竞赛的“可核查引用”不能只停留在编号对齐。

为什么这么做：nature-ref-verifier 把引用核验变成一个确定执行的清单：先 Crossref 解析 DOI，失败再 PubMed/S2/Web 兜底；逐字段比对作者顺序、年份、卷期、页码、标题核心词；输出 Critical/Warning/Info 分级与 Verified/Check suggested/Needs fix/Unverifiable 四级置信度，并给 BibTeX 补丁。它证明“引用对不对”是可以程序化回答的，而不是让 reviewer 凭感觉。

成本：需要 Crossref（已在规划）和标题/作者解析。MVP 先做“DOI 解析 + 标题年份作者比对 + 分级报告”，页码/CNKI 深度对比留 M3。

## D. 全文获取与阅读

为什么需要：这是用户直接点名的问题。没有全文，writer 只能基于摘要编，写作质量必然差。

为什么这么做：nature-downloader 与 science 的 EuropePMC/arXiv/OpenAlex 下载都遵循同一套：OA 优先（PMC/Unpaywall/arXiv/publisher OA）、publisher API 可选、机构访问只在用户授权会话内、下载后校验 PDF 非空可读、记录来源与状态清单。这样既提升证据质量，又规避版权风险。

成本：M2-7 已规划 top-N 全文注入；M2-8 补上“PDF 校验 + 状态清单 + 来源审计”。MVP 必做。

## E. 精读卡片（16 节 schema + 证据标签）

为什么需要：我们现在的“论文卡片”只是元数据（标题/作者/引用/摘要），不承载“方法、证据链、结论边界”，writer 拿它写不出严谨综述。

为什么这么做：nature-paper-card 的 16 节强制区分“作者说的”和“我推断的”，证据标签 `[Paper]/[External]/[Analysis]/[Hypothesis]/[User]` 是防幻觉的关键；claim 强度动词（reports/suggests/causes 的差异）让结论有据。这是我们评审叙事里“可追溯”的落点。

成本：16 节全量很重，且依赖全文与源定位。建议 M3 做独立 Reader 角色，MVP 只定义精简卡片 schema（一句话结论、核心方法、可引用要点、证据标签）给 writer，不一步到位。

## F. 审查规范（concern ledger）

为什么需要：我们的 reviewer 输出是自由文本，无法结构化知道“哪些是阻断、依据哪张卡片、怎样算解决”。人审批时缺一个可执行清单。

为什么这么做：nature-reviewer 的 concern ledger（severity/blocking/claim_pointer/evidence_pointer/resolution_test）让每一条意见都可追踪、可复核；“不可变审查包 + 审查者隔离”防互相污染。MVP 先做单一 reviewer 的结构化 ledger，多审查者隔离留 M3。

成本：中等，主要是提示词与输出结构改造，配合引用核验一起做收益最高。

## G. 写作规范（对齐门 + claim-evidence map）

为什么需要：真实运行草稿覆盖缺失、借位引用、格式漂移，本质是没有“写前对齐”和“写后核查”。

为什么这么做：nature-writing 的“一句话论点 + 段落图先确认 → 从证据往外写 → 动词匹配证据强度 → 输出 claim-evidence map → 定向修改”，直接对症“写出来不是我要的”和“引用不可核查”。对齐门尤其关键，能避免一整篇写错方向。

成本：MVP 至少做“对齐门 + claim-evidence map + 强制 `[n]` 引用”，术语表与全文改写策略留 M3。

## H. 评估评分（六维 + gap 分析）

为什么需要：现在无法客观衡量一次调研好不好，只能靠人看。竞赛和迭代都需要量化。

为什么这么做：literature-pipeline 的六维评分把“主题匹配 35 分门禁 + 方法/期刊/网络/应用/存档”变成可校准的量化；gap 分析保留检索方法与命中数，保证可复现。主题匹配门禁尤其重要，能挡住“高引用但不相关”的论文。

成本：完整六维需要多次评分（模型或规则）。MVP 做“主题匹配门禁 + 相关度分 + 大纲覆盖”，完整版留 M3。

## I. 工程规范（封装 CLI / 限流 / 凭据 / 文件输出）

为什么需要：限流、错误处理、context 溢出是重复工程债，尤其大量 API 返回 JSON 会撑爆上下文。

为什么这么做：science-skills 的范式是“封装 CLI、--output 写文件、限流退避、错误体回传、凭据只走 .env”。研镜已有一半（client 限流、错误体），补齐“结果写文件避免 context 溢出”和“凭据协议”即可，成本低收益高。MVP 必做。

## 优先级切分建议

清单不是一次全做。按“MVP 必做 / 留 M3”切一刀，避免过载：

| 项目 | MVP 范围 | 留 M3 |
|------|----------|-------|
| A 分层路由 | 建 manifest + 关键片段（检索/核验/写作/审查） | 全量片段与可视化编辑器 |
| B 检索规范 | 源分级路由、查询构造、去重兜底、限流 | 机构授权源（PubMed/CNKI） |
| C 引用核验 | DOI 解析 + 标题年份作者比对 + 分级报告 | 页码/CNKI 深度比对、BibTeX 补丁 |
| D 全文 | OA 优先下载 + PDF 校验 + 状态清单 + 全文注入 writer | publisher API 与机构会话 |
| E 精读卡片 | 精简卡片 schema + 证据标签 | 独立 Reader 角色 + 16 节全量 |
| F 审查 | 单一 reviewer 的 concern ledger | 多审查者隔离 |
| G 写作 | 对齐门 + claim-evidence map + 强制 `[n]` | 术语表、逐段改写策略 |
| H 评估 | 主题匹配门禁 + 相关度分 + 大纲覆盖 | 六维完整评分 + gap 分析 |
| I 工程规范 | 限流 / 错误体 / 文件输出 / 凭据仅环境变量 | 无 |

这样 M2-8 与 M2-7 合并后，主线仍是“检索 + 证据 + 引用 + 写作”四件事的闭环，其余作为 M3 增强。
