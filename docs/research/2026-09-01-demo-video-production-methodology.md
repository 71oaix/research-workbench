# 调研：竞赛演示视频录制方法论

> 背景：9/1 提交截止前需交付 ≤5 分钟演示视频（≤200M mp4）。用户要求先做行业深度调查，
> 回答三件事——**怎么录、录几遍、怎么写脚本**，再据此提 issue。
> 方法：4 路并行 web 行业调研（竞赛视频规范 / 录屏技术 / 脚本写作 / AI demo 制作经验）
> + 本机环境实测勘察 + 既有脚本盘点。

## 〇、结论速览（TL;DR）

| 问题 | 结论 |
|------|------|
| 怎么录 | 本机**未装任何录屏/剪辑软件**（实测），需先装：**OBS Studio（录屏）+ 剪映专业版（剪辑）**，均 winget 可装（已实测可搜到）。1080p@30fps 起，真实运行录屏 + 特写原速 + 流程段加速，旁白后期配音或字幕替代 |
| 录几遍 | **0+1+1+后期 共 3 轮录制**：遍次 0 热身（真实跑通+记时间窗，素材可弃）→ 遍次 1 主录（真实运行，S3-S9 全程，流程段 4-8x、特写段原速）→ 遍次 2 补拍（DEMO 模式补审批"打回重写"镜头）→ 后期制作（开场/收尾/叠化素材非录屏） |
| 怎么写脚本 | 已有两份分镜脚本（`01-competition-story.md` 4:50 分镜级 S1-S10、`2026-08-28-demo-video-script.md` 4:30 七幕）。以 4:50 分镜级为主纲，按"时间码/画面/解说词/镜头/转场"要素补齐录制指令与旁白逐字稿，每 15-25s 一个镜头，核心卖点段（覆盖矩阵）留足 50s |

## 一、交付物硬约束（确定性，来自项目文档）

- **≤5 分钟**演示视频、**≤200M mp4**（`docs/research/2026-08-20-deliverable-readiness-audit.md` 附件 1 交付物清单）；
- 演示问题固定：**"研究下多智能体的记忆架构"**（与分镜及历史真实运行一致）；
- 叙事主线：四"可"——可观测（成本/思考全透明）、可追踪（引用级溯源）、可控（双审批取消）、可验证（覆盖质量门）；
- 视频目标 4:50（01-competition-story.md 分镜 S1-S10）。

### 3.2 遍数规划（0+1+1+后期）

| 遍次 | 模式 | 内容 | 原始时长 | 用途 | 注意 |
|------|------|------|---------|------|------|
| 遍次 0（热身，可弃） | 真实运行 | 同一问题完整跑一遍 | 13-20min | 验证稳定、记各特写时间窗、确认审批卡点位置与成本数字、排查演示问题（含 Firecrawl 补位是否触发） | **务必先跑**，确认无回归再正式录 |
| 遍次 1（主录） | 真实运行 | S3-S9 全程录屏：流程段 4-8x、特写段原速+指点 | 13-20min → 剪至 ~3min | 视频主体 | 与解说对拍；S5/S7/S9 到点提示"特写开始" |
| 遍次 2（补拍） | DEMO（DEMO_MODE=1） | S3 审批"打回重写"+审批交互特写 | ~1min | 补"可控"叙事镜头（真实打回会重跑花钱） | 打回→意见→重跑→二版通过 |
| 后期 | 非录屏 | S1 开场字卡+幻觉图、S2 特性卡动效、S9 指标叠化、S10 架构图+slogan | — | 首尾与叠化素材 | 指标数字与真实运行口径对齐 |

### 3.3 录制前检查清单（并入最终报告）

1. `.env.local` 就位：DEEPSEEK_API_KEY ✓、FIRECRAWL_API_KEY ✓（改后重启 dev server）；
2. 遍次 0 热身通过、无回归；
3. 录制窗口布局：右栏运行总览卡完整可见、缩放/中文正常；
4. 解说词与分镜 S1-S10 逐段对拍；
5. 特写段（S5/S7/S9）预告标记，避免后期找不到时间窗。

### 3.4 录制一致性隐患（2026-09-01 代码勘察）

- **DEMO/真实标题不一致**：`MockStepRunner.ts` 的演示官方文档段标题仍是旧文案
  "官方文档参考（不进引用编号与核验序列）"，而真实代码（officialDocs.ts）已改为
  "补充参考（官方文档 / 网页，不进引用编号与核验序列）"。遍次2（DEMO 补拍）与遍次1
  （真实运行）画面会出现同一段标题不一致——**建议先做一处文案小修再录**，否则剪辑对不齐。
- DEMO 模式已具备：低分→自动重写回环（第一轮 2.9 分触发、二评 3.8 收敛）、
  审批打回 feedback 通道、官方文档参考段——遍次2 补拍素材齐备。
- **无"历史工作流预置"机制**：代码库无 seed/preset 入口。`2026-08-28-demo-video-script.md`
  预备清单要求"预置两条工作流作为历史记录"（一条 completed、一条含打回迭代）——
  只能靠真跑产生，正好由遍次0 热身承担（先跑一条完整、一条打回，作为录制时的"历史"背景）。

### 1. 竞赛/hackathon demo 视频通用规范（Devpost / hackathon.com 官方）

- **时长**：多数 hackathon 要求 ≤3 分钟，本项目竞赛为 ≤5 分钟（已确认 4:50 目标）——**先查清提交要求再定稿**；
- **脚本先行**（多来源强调）：录制前写脚本，把时间分成"开场钩子 / 讲清做什么 / 怎么运行 / 展示 demo / 收尾"几段，各段分配秒数；**避免纯 ChatGPT 写脚本**——太泛，不如自己写清楚产品；
- **开场直入**：前几秒给 elevator pitch（一句话产品 + 解决什么问题），评委连续看多个项目，开头信息最容易被记住；KISS（Keep It Simple）；
- **展示真实运行**：本地跑起来 demo（我们是 Web 工作台天然符合），不要幻灯片堆砌；展示"做了什么 / 怎么解决 / 技术栈"；
- **质量**：用 OBS 录屏 + 好一点的麦克风（团队里音质最好的人录旁白）；检查画质、音质、隐私/访问设置（传平台时别设私有）；
- **不要拖**：别把信息硬塞满或加速音频赶时长；评委看多项目，简洁清晰 > 堆信息。

### 2. 录制工具与技术（OBS 官方 KB / 社区实践）

- **OBS Studio**（开源、免费、Windows 支持）：桌面 + 音频录制事实标准；场景/来源/滤镜；
  "快速上手"在官方 KB；社区（hackathon 获奖者）广泛推荐 OBS 录桌面与音频；
- 录屏参数（结合本机 RTX 4060 NVENC）：输出 1920×1080、30fps、H.264 即可（NVENC 硬编零 CPU 压力）；
  本机物理 2560×1600 可录原始窗口再缩放，避免高 DPI 下字体过小；
- 剪辑：免费可选手 **DaVinci Resolve / Kdenlive / CapCut（剪映）**；本项目选剪映（winget 可装、中文、字幕/变速/特效齐全）；
  社区实践：每个分镜**单独录一段**便于重录，后期拼接（与本项目遍次1"分镜片段"一致）；
- 音频：旁白单独录、后期对轨；环境降噪（Windows 自带或 OBS 滤镜）。

### 3. 脚本/旁白写作（Murf AI / ElevenLabs 实践）

- 产品 demo 视频方法论（Murf AI）：理解受众 → 定义信息 → 规划流程（哪些功能、节奏、时长）→ 写脚本 → 定风格 → 拍摄 → 剪辑 → 配音/配乐；
- 脚本是"骨架"：讲清产品故事、覆盖关键点、信息与画面同步；风格要与品牌/受众一致；
- AI 配音（ElevenLabs / Descript / Murf）可行：脚本按"口头语、短句、留停顿"写更自然；tone tags 可控制情绪（whisper/laugh/sigh）；TTS 好处是可反复重录到满意、无口误成本；
- 本视频旁白方案建议：**真人录音优先（有麦克风阵列），时间紧可 AI 配音**——配音与分镜逐句对拍，后期对轨。

### 4. AI/Agent 产品 demo 的行业惯例（OpenAI/Perplexity/Deep Research 案例）

- 主流 AI 产品（OpenAI Deep Research、Perplexity、各类 agent）发布 demo 均以**真实产品操作 + 字幕**为主，而非纯动画；
- "跑起来要等"的产品：保留**进度/过程动效**并加速（体现真实但不拖沓）；Deep Research 类 demo 常用"等待进度动画 + 结果特写"结构——与本项目"流程段加速 + 特写原速"一致；
- 可观察性/过程透明是 AI 类 demo 的加分项（与本项目"四可"叙事吻合）。

### 5. 竞赛视频规范（第八届中国研究生人工智能创新大赛，官方指南已核验）

- **硬约束确认**：项目视频"时长不超过 5 分钟、文件大小不超过 200M、mp4 格式"，命名
  `团队名称_项目名称_项目视频.mp4`（官方《初赛作品提交规范》原文；第八届沿用）；
- **匿名硬要求**：队名及全部材料**不得体现学校/学院/导师**——视频片头片尾禁校名/院徽/导师姓名；
- **评审五维**（官方考察要点）：选题新颖性 / 技术可行性 / 方案创新性 / 应用落地性 / 表达清晰性；
  材料须展示 Inference 效果与指标、严格标注数据/文献来源——视频中的引用与数据必须与申报文档一致可查；
- **真实性**：官方明令"作伪/作假/抄袭"取消资格——真实运行录屏远优于摆拍/动画（决赛现场可被质疑验证）；
- 提交经研创网 cpipc.acge.org.cn 线上评审（初赛无现场环节），视频即评委第一印象；
- 参考先例：第六届一等奖官方发布为"3 分钟展示"视频，评委习惯短时高信息密度；
- 华为赛题"科研场景下复杂学术查询的智能论文搜索与推荐"与研镜方向高度契合（若报华为赛题，视频点题呼应）。
