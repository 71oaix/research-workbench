# 效果基线：检索评测 + 成本指标 + 真实运行对比

## 一、离线检索评测（recall@20，全量版 vs 无迭代基线）

口径：

- 自建 10 条查询（宽泛 + 精确混合，双语检索式，模拟 planner 改写；见 `data/eval/`）；
- 只覆盖确定性检索段（不含澄清、selector 分级、引文雪球——这些由真实运行口径衡量）；
- 基线 = 仅关键词组（无子问题合并 / 时间过滤 / 引文雪球 / 分级排序），同义词扩展为生产行为保留；
- 金标为手工标注标题，按“标题 + 摘要”包含匹配且金标去重计数；开源源（OpenAlex/S2 无 key）限流失败会如实计入。

结论与局限：

- 单查询离线检索对“金标是特定论文”的场景偏保守：arXiv 查询被精简到前 3 实词、
  部分源限流失败、金标论文标题不含查询词等都会拉低 recall；
- 真实工作流中 planner 会把宽泛问题拆成多组子查询，selector 按摘要筛选、
  引文雪球补候选，这些收益由第二节的真实运行指标体现；
- q10 全量版显著优于基线（50% vs 25%，+25pp），说明查询组扩展对“评测类”查询有效。

## 三、成本指标（usage_records 聚合，deepseek-v4-flash，xhigh 思考）

| 模板 | 模型调用 | 输入 token | 输出 token | 成本(¥) | 端到端耗时 |
|------|----------|------------|------------|---------|-----------|
| 七步完整（含 writer） | 7 | ≈188k | ≈57k | ≈0.31 | ≈13 分钟 |
| 六步调研（无 writer） | 8 | ≈145k | ≈74k | ≈0.30 | ≈14 分钟 |

说明：

- 耗时 = usage_records 首尾时间差，含审批等待，真实执行时间更短；
- 复现：`npx tsx scripts/cost-report.mjs`；
- 缓存命中显著（cache_read 6.5-56 万 token），进一步压低成本；
- 对比：M2-14 单次运行 ≈¥0.22-0.40；M2-15/16 检索广度提升（命中 3 倍）后
  成本仍控制在 ≈¥0.3，性价比提升。
