## 二、思考过程审核（pi 会话记录）

- **planner（max）**：深度拆解有效——记忆分类、共享/分布式/层级形态、框架工程实践等锚点全部命中，产出可直接执行。
- **researcher**：忠实于卡片，主动识别 [7] 元数据异常并如实保留，不美化不猜测。
- **writer**：正确识别“只有前 3 篇有全文摘录”、主动排除 [7]；但引言证据声明写错（C8）——根因是证据池把“全文已读”与“已注入摘录”两个概念混在一起：卡片标“全文已读 7”，摘录区只注入 3 篇，模型按“只有 3 篇全文”理解。修复：摘录区需显式写“已读 7 篇，此处仅注入前 3 篇摘录，其余仅可引摘要”。
- **reviewer**：通读全部自动报告，正确消化 11/12 unverifiable 的原因（arXiv 429）并降级为 Not assessable，未误报引用错误；对全文级 claims 全部标注待核验。证明“模型可靠 + 流程透明”的叙事成立。

## 三、评估报告机制说明与失真分析（用户反馈“很诡异”）

### 现在的机制（代码事实）

1. **主题词集**：从 plan 的“检索关键词”小节（无则“锚定点”）tokenize——英文按词、中文按 bigram，本次得到 44 个词。
2. **主题命中率**：每张卡片（标题 + 摘要前 400 字符）与主题词集**有任意交集即命中**；命中率 = 命中卡片数 / 卡片数；门禁 0.4。
3. **相关度**：每张卡片覆盖度 = 与主题的交集词数 / 44（主题词总数），输出均值与中位数。
4. **大纲覆盖**：plan“综述大纲”里编号标题与草稿标题做 tokenize Jaccard ≥ 0.5 或含任一核心词。
5. **来源失败**：从原始卡片解析“失败源”行，原样逐条列出。

### 为什么看起来诡异

- **命中率恒 1.00**：判定是“任一卡片含任一主题词”——44 个词的并集几乎保证任何相关卡片都命中，门禁形同虚设、无区分度。
- **相关度 0.10 且均值=中位数**：分母是全部 44 个词，单篇论文不可能覆盖 44 词，所以所有卡片都低分且分布扁平（0.10 附近）；评委看到 0.10 会误以为系统检索质量差。
- **大纲覆盖只比标题**：不检查章节是否真的写了内容、是否引用了卡片（空标题也算覆盖）。
- **失败源噪音**：19 条 T2 限流失败原样搬进评估报告，观感差且与“评估”无关。

### 重设计方向

- 主题词改用“锚定点核心概念”（人工可读、数量 ≤20），不用关键词并集；
- 命中率改为“每组关键词至少命中 1 张卡片”（召回面）或“核心概念覆盖数 / 概念总数”；
- 相关度改为卡片侧 Jaccard（交集 / 卡片自身词数）或分组命中率，输出分布（P25 / P50 / P75）；
- 大纲覆盖加“内容锚点”：标题命中后检查该章节至少引用 1 张卡片；
- 失败源在检索概览保留明细，评估报告只给“失败源数量 + 影响查询数”。

## 四、为什么“只下载了一半”（根因）

代码事实：`researcherStep.ts` 只对 `papers.slice(0, readTop)`（`SEARCH_READ_TOP` 默认 8）尝试下载；
15 张卡片中仅前 8 篇被尝试 → 7 成功 + 1 无开放获取（[7] 元数据损坏、无 PDF 候选）。
数据库证据：303 篇 papers 的 `download_status` 为 null（从未尝试）。

结论：**不是下载失败，是只尝试了前 8 篇**；且论文表显示大量未尝试论文本身带 arXiv ID / URL，提高覆盖会显著提升成功篇数。

修复方向：
1. 对全部卡片中有 OA 候选的论文尝试下载（受时间预算约束），或提高 `SEARCH_READ_TOP`；
2. 下载与 writer 执行并行（后台补齐剩余篇目）；
3. 对无候选论文补充 OpenAlex `best_oa_location` / Unpaywall 候选。

## 六、竞赛叙事建议（评审官角度）

- **作品定位**：“可审计证据链的科研调研智能体”。创新点是透明可观测——artifact 版本链、角色思考记录、逐步成本、WS 实时、人审批点；不是“复刻 Codex”。
- **演示脚本**：绑定一个代表性领域问题（建议“AI 方向文献综述”），展示 规划 → 检索 → 下载 → 写作 → 核验 → 审查 → 打回 → 收敛 全闭环；重点展示 04-review 的 Concern Ledger 与打回后 v2 的改进对照。
- **讲数据**：下载成功率、核验通过率、耗时/成本、多轮收敛；当前核验 1/12 必须修复，否则演示在“引用真实性”环节翻车。

## 结论

- P0（建议本轮 M2-13）：引用核验批量与兜底（arXiv id_list 批量 + Crossref 兜底）、评估指标重设计。

- P2：大纲内容锚点、计划-检索能力对齐、元数据异常过滤。
