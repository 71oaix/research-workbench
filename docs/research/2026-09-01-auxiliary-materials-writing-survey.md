# 调研：第八届人工智能创新大赛"可选辅佐材料"写作调研

> 背景：研镜 Research Workbench（开放赛题一"生成式大语言模型与智能体"）需补齐"其他可选辅佐材料"。本文档回答：官方怎么定义、可研/尽调报告怎么写、评委看什么、研镜写什么。
> 检索通道说明：web_search 通道故障，改用 Bing/360/DDG html 检索 + 直接抓取官网原文；标注"推断"处为通行惯例而非官方条文。

## 一、辅佐材料官方定义与常见类型

**官方原文**（第八届《参赛邀请函》《参赛指南》一致）："参赛者须根据赛题作品规范提交参赛作品简介（无模板，300 字以内）、项目文档（基于标准模板完成项目内容的详细阐述）、项目视频（充分展示团队成果）、**其他可选辅佐材料（技术可行性、产品尽职调查报告等项目相关内容）**"。第五届时邀请函即有此表述，属长期惯例。

**附件 1《初赛作品提交规范》补充**："（4）其他辅助材料（技术可行性等项目相关内容）**不局限于论文、可执行程序、项目代码等最终呈现形式**"，以 zip 压缩、≤200M、命名为"团队名_项目名_其他.zip"（注意：文件内与全部材料中不得出现学校/学院/导师信息）。

**常见类型**（规范允许范围 + 惯例归纳）：①技术可行性报告（官方点名）；②产品尽职调查报告（官方点名）；③评测/对比实验记录与数据；④用户调研/试用反馈；⑤市场与竞品分析；⑥论文/预印本、代码与可执行程序、演示用数据包；⑦开发日志/里程碑（佐证"大赛期间独立完成"）；⑧专利/软著等佐证。**建议口径**：zip 内放"报告类 + 数据/代码类"两类，报告为入口、数据为证据。

## 二、技术可行性报告结构惯例

大赛无统一模板（项目文档模板仅在第 3.1 节要求"阐述数据如何采集、行业知识如何获取、算力硬件支持、预期技术指标"）。综合真实样例与通行惯例（部分为推断）：

1. **调研目的与范围**：平台/系统定义、要验证的关键假设（模型能力、编排、检索、成本）；
2. **测试环境与方法**：模型/API 清单、硬件、测试方法与判定标准（分层测试）；
3. **能力验证**：逐项给出**输入→方法→结果→判定**表，只写已跑通的真实数据；
4. **核心架构验证**：编排、并发、隔离、鲁棒性（重试/熔断/预算）；
5. **风险矩阵**：技术/数据/合规/供应商风险 × 概率 × 影响 × 应对；
6. **成本与规模估算**：token/请求单价→单综述成本→规模化测算；
7. **结论**：可行/有条件可行 + 剩余风险。

真实样例见 [GitHub: AI 情感 Agent 平台技术可行性分析](https://github.com/anrror/y-ai-accompany/blob/master/doc/%E6%8A%80%E6%9C%AF%E5%8F%AF%E8%A1%8C%E6%80%A7%E5%88%86%E6%9E%90.md)（结构即上 7 项）；《产品开发技术可行性分析报告模板》（文档网，抓取被 403，仅据检索摘要：目录含"系统概要/系统方案"）。

## 三、产品尽职调查报告结构惯例

**大赛无官方模板（未查到任何官方范本）**，术语借自投资尽调。结构性基准可参照证监会《保荐人尽职调查工作准则》（2022 修订版官方 PDF 可公开访问）：总则、风险因素、发行人基本情况、业务与技术、财务、公司治理等章节；配套见中证协《证券业务示范实践第 3 号—保荐人尽职调查》。按其精神简化为学生作品适用的"产品尽调"框架（推断）：

1. 产品定义与价值主张（解决什么问题、给谁、为什么现在）；
2. 技术成熟度评估（TRL 或"原型→验证→可规模化"分级，与可研报告呼应）；
3. 合规与来源：数据来源与许可、模型/开源许可证、隐私、引用标注；
4. 竞争格局：直接/间接竞品矩阵（功能×价格×透明性），差异化；替代方案（人工综述、通用 Agent）；
5. 市场空间与定位：目标用户、TAM/SAM/SOM 或"科研场景锚点"式测算；
6. 用户与需求验证：访谈/试用反馈、付费意愿或使用意愿；
7. 商业模式与成本结构：定价、成本透明（token 成本=研镜卖点）、单位经济模型；
8. 风险清单与应对：模型幻觉、检索源不可用、竞品跟进。

## 四、评委加分点与减分点

**官方给出的考察维度**（《参赛指南》）："评审专家根据作品的**选题新颖性、技术可行性、方案的创新性、应用落地性及表达清晰性**等方面制定评审标准"；附件 1 要求材料写明：①创新性严谨论证；②技术调研与**已有工作对比分析**；③**AI 技术在 Inference 上的效果和指标**；④**数据、行业知识、算法、硬件来源**与引用标注。华为企业赛题专家评分同样落在"方案的新颖性、合理性"。

**加分项**（对应维度）：真实运行数据与量化指标（一次端到端真实 demo 的指标表，比任何描述有力）；与现有工具/方案的对比实验（含基线）；用户/试用反馈与访谈记录；市场定位与竞品矩阵；合规与引用标注完整；成本测算（研镜独有"成本透明"）；表达上用图/表/截图而非纯文字。

**减分项**（推断，据考察维度 + 华师校赛"材料不完整、不合规直接淘汰"）：凑数堆砌与主题无关的素材；无数据支撑的空话；把计划写成已验证成果（评委核实时直接穿帮）；命名/格式不合规（zip ≤200M、命名规则、泄露校名导师）；正文与附件数据口径冲突；内容超出 5 分钟视频/300 字简介能支撑的预期而"文不符实"。

## 五、针对"研镜"的辅佐材料建议清单（优先级）

| 优先级 | 材料 | 写什么（对应研镜证据） |
|---|---|---|
| P0 | 技术可行性报告 | 真实运行复盘：检索 recall/覆盖矩阵、引用核验通过率、端到端时长、成本表（报告《效果基线》已有数据可直接迁移） |
| P0 | 对比实验报告 | 研镜 vs 通用 ChatGPT/手动调研：同一研究问题，输出质量（引用可溯源）、耗时、成本、覆盖差距 |
| P1 | 产品尽职调查报告 | 科研"透明学术调研"市场定位、竞品矩阵（Elicit/Consensus/NotebookLM/通用 Agent 助手，外部资料+推断）、商业模式与成本透明、用户访谈纪要 |
| P1 | 用户调研/试用报告 | ≥5 名真实试用者问卷+访谈+问题工单记录 |
| P1 | 开发日志/版本里程碑 | 佐证"大赛期间独立完成"，与仓库历史一致 |
| P2 | 代码/演示数据包 | zip 合规命名，含仓库快照+示例输出 JSON/综述产物 |
| P2 | 透明性白皮书 | 七角色流水线+双审批+引用核验机制说明（呼应"表达清晰性"） |
| 不做 | 无数据支撑的"未来规划"类材料 | 纯凑数，反而暴露预期与成果落差 |

**操作结论**：官方点名两类（可研+尽调）务必写，zed 内以"真实数据"为硬门槛；对比实验与用户反馈是普通队伍最缺而研镜最占优势的两块，P0 先做。
