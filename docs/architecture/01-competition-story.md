# 01 · 竞赛叙事与答辩预设

## 一句话作品

研镜（Research Workbench）——让研究生用一杯咖啡的时间完成原本一周的文献调研初稿：每一步可查、每句引用可溯源、成本可控。

## 我们解决的痛点

1. **耗时**：选题、开题、写 Related Work，要读几十篇论文，检索、筛选、精读、归纳全靠手工。
2. **AI 综述不敢用**：黑盒生成，引用可能是幻觉，导师一问就穿帮。
3. **过程不可控**：全自动怕跑偏，全手动又太慢。

## 解决方案（演示主线）

输入研究问题 → Planner 生成检索计划（人审）→ Researcher 跨多个学术源检索 → 证据卡片（摘要 / DOI / 引用数）→ Writer 生成带引用标注的综述初稿 → Reviewer 核查引用真实性与覆盖度 → 成品审批 → 导出综述 + 引用清单。

## 三支柱（每一条都要能演示）

- **可观测**：每个角色的思考、工具调用、系统提示词、上下文占用、人民币成本实时可见。
- **可追踪**：综述里每句论断绑定论文 + 证据片段，可跳原文；artifact 有版本历史。
- **可控**：计划与成品两个强制审批点；预算超限自动暂停；可随时插入意见从当前步继续。

## 与 Codex / DeepSeek Harness 的区别

| 维度 | 通用 Harness | 研镜 |
|------|-------------|------|
| 定位 | 通用任务执行引擎 | 科研领域工作台 |
| 交接 | 动作 / 对话 | 产物文件（artifact） |
| 人类参与 | 开始给指令、结束改结果 | 审方案、审成品；中间自动但可见 |
| 引用 | 不保证 | 引用级溯源 + 审查 |
| 透明 | 黑盒 | 提示词 / 上下文 / 成本全透明 |

## 5 分钟演示脚本

1. 输入一个真实研究问题（如“大语言模型在软件测试中的应用”）。
2. Planner 生成检索计划：子问题、关键词、综述大纲（展示步骤视图）。
3. 用户审批计划。
4. Researcher 实时检索 Semantic Scholar / OpenAlex / arXiv，工具调用可见。
5. 展示论文卡片：相关性、摘要、DOI、引用数。
6. Writer 生成综述初稿，每个论断带引用标注。
7. Reviewer 输出核查意见：哪些引用可信、哪些存疑、哪些方向覆盖不足。
8. 用户审批成品，导出 Markdown + 引用清单。
9. 收尾展示可观测面板：成本、上下文、各角色系统提示词。

## 答辩预设 Q&A

- **“这不就是 Codex 吗？”** 定位不同：Codex 是通用任务执行引擎，追求更快更强；研镜是科研领域工作台，创新在多角色编排、产物交接、审批治理与引用溯源。
- **“这不就是包了一层 pi 吗？”** 分层回答：pi 提供的是单智能体执行器（等价于用 OpenAI SDK）；我们构建的是 WorkflowEngine 编排、artifact 交接、双审批流、引用级溯源与可观测 UI。
- **“创新点在哪？”** 三支柱 + 产物级交接 + 引用级溯源；编排者是服务端代码与人类，而不是黑盒的 agent 嵌套。
- **“效果怎么证明？”** 端到端演示 + Reviewer 核查结果 + 成本与覆盖率数据（评测脚本见 P1）。
- **“用的什么模型？”** 模型无关：OpenAI 兼容接口，DeepSeek / Qwen / OpenAI 均可，用户自带 key。
- **“局限与未来？”** 当前以国际学术文献为主；未来做 PDF 精读、中英文文献、自定义工作流模板、团队协作。
