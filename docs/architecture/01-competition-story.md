# 01 · 竞赛叙事与演示视频脚本

> 2026-08-31 全量改版：对齐七角色 + M4 覆盖质量门 + 运行总览卡的最新状态，演示脚本升级为分镜级视频脚本（含解说词与镜头要求），供录制直接使用。

## 一句话作品

研镜（Research Workbench）——让研究生用一杯咖啡的时间完成原本一周的文献调研初稿：每一步可查、每句引用可溯源、成本可控。

## 我们解决的痛点

1. **耗时**：选题、开题、写 Related Work 要读几十篇论文，检索、筛选、精读、归纳全靠手工；
2. **AI 综述不敢用**：黑盒生成，引用可能是幻觉，导师一问出处就穿帮；
3. **过程不可控**：全自动怕跑偏，全手动又太慢。

## 叙事主张：别人比"多快"，我们比"多可信"

同类工作大多演示"生成多流畅"；研镜的核心命题是 **AI 综述如何才能被信任**。
四个"可"，每一条都要能在视频里给出对应镜头：

| 支柱 | 含义 | 对应镜头 |
|------|------|----------|
| **可观测** | 每个角色的思考、系统提示词、工具调用、人民币成本实时可见；运行总览卡（状态机 + 按角色成本条形图）一眼看全 | 总览卡特写，成本数字随角色推进增长 |
| **可追踪** | 综述每个论断绑定论文卡片与摘要证据；引用经 Crossref（DOI 字段级）+ arXiv（批量）多源交叉核验，输出可信/存疑分级报告 | 核验报告特写，逐条勾稽 |
| **可控** | 计划与成品双审批点，打回修改多轮迭代；宽泛问题先澄清锚点；运行中可引擎级取消 | 审批卡交互、停止按钮 |
| **可验证** | 覆盖质量门：计划子问题 → 证据池覆盖矩阵（覆盖/部分/缺失），缺口自动二次检索回环（≤3 轮）+ 模型辅助精判；"计划的问题条条有文献支撑"是可验证命题而非口号 | 覆盖矩阵特写 + 缺口行 + 补检后复判 |

## 七角色流水线（演示主线）

输入研究问题 → **planner** 生成检索计划（澄清/子问题/关键词/大纲，人审）→
**researcher** 四源并发检索（arXiv / Crossref / OpenAlex / Semantic Scholar）→
**selector** 筛选分级 + 覆盖质量门（覆盖矩阵 + 缺口补检 + 引文雪球）→
**writer** 带引用标注综述（流式 + 思考可见，人审）→ **evaluator** 六维评估 →
**reviewer** 引用逐条核验分级 → **summarizer** 主题分组 + 引用清单 →
导出（Markdown / BibTeX / APA / GB-T）。

角色间不共享上下文，仅通过产物文件（artifact）交接，隔离上下文污染；编排者是服务端引擎与人类，不是黑盒嵌套。

## 与通用 Agent / Harness 的区别

| 维度 | 通用 Harness（Codex 类） | 学术检索 Agent（PaSa / SPAR 类） | 研镜 |
|------|-------------|-------------|------|
| 定位 | 通用任务执行引擎 | 论文检索打榜 | 科研调研全流程工作台 |
| 交接 | 动作 / 对话 | 检索结果列表 | 产物文件（artifact，带版本） |
| 人类参与 | 开始给指令、结束改结果 | 无 | 审方案、审成品；中间自动但可见 |
| 引用 | 不保证 | 不核验 | 引用级溯源 + 多源核验分级 |
| 覆盖 | 不检查 | 无 | 子问题覆盖矩阵 + 缺口自动补检 |
| 透明 | 黑盒 | 黑盒 | 提示词 / 思考 / 成本全透明 |

## 演示视频分镜脚本（目标 4:50，≤5 分钟）

> 素材：真实运行为主线（录屏 1080p，流程段 4-8 倍速，特写原速）；DEMO 模式仅补审批交互镜头。
> 演示问题（与历史验证一致）："研究下多智能体的记忆架构"。
> 录屏时右栏"运行总览卡"全程在画面内（成本条形图随角色推进生长，是最强的可观测证据）。

| # | 时间 | 画面 | 解说词 |
|---|------|------|--------|
| S1 | 0:00-0:15 | 黑屏白字："AI 一小时写好综述，但你敢交给导师吗？"。切一张"引用不存在"的幻觉示例（静态图） | 大模型几分钟能生成一篇综述，但引用可能是编的——导师一问出处就穿帮。 |
| S2 | 0:15-0:35 | 研镜首页 → 三张特性卡（可观测 / 可追踪 / 可控 / 可验证四选三动效） | 研镜把文献调研变成一条透明流水线：七个角色分工协作，人在关键节点把关，每句引用都有出处。 |
| S3 | 0:35-1:00 | 输入"研究下多智能体的记忆架构" → planner 流式生成计划（子问题/关键词/大纲）→ 审批卡点"通过" | 输入研究问题，规划角色先拆解子问题、检索关键词与综述大纲；宽泛问题会先澄清。计划需要人工审批，不满意可以打回重写。 |
| S4 | 1:00-1:40 | 检索过程：命中/去重数字跳动（加速），论文卡片列表（年份/引用数/来源/摘要） | 四个学术数据源并发检索、实时去重。每篇候选都带年份、引用数与摘要，相关性分级一目了然。 |
| S5 | 1:40-2:20 | **覆盖矩阵特写（原速停 15 秒）**：coverage-matrix 表格逐行扫过；停在"缺失"行与缺口建议；切补检后矩阵更新 | 这是研镜的覆盖质量门：计划的每个子问题是否被文献支撑，矩阵逐条可查；发现缺口自动发起二次检索补齐，模型还会复核判定。"调研覆盖够不够"从感觉变成了可验证的结论。 |
| S6 | 2:20-2:50 | Writer 流式写作：正文 + 思考块同屏滚动，引用标注 [n] 高亮 | 写作角色按大纲成稿，每个论断带引用标注，思考过程实时可见——不是黑盒。 |
| S7 | 2:50-3:20 | **核验报告特写（原速停 15 秒）**：citation-lint 编号勾稽 → 审查报告"可信清单 / 存疑引用"分级 | 审查角色逐条核验引用，与 Crossref、arXiv 交叉比对，输出可信与存疑分级——这是敢把结果交给导师的底气。 |
| S8 | 3:20-3:40 | 导出：05-summary（主题分组+引用清单）与 references.bib | 最终产出主题分组摘要与结构化引用清单，BibTeX、APA、国标格式直接进论文工作流。 |
| S9 | 3:40-4:20 | **总览卡特写**：¥ 大数字 + 按角色成本条形排行；叠化指标表（命中/去重 1259+、入选 15-21、核验率、耗时 13 分钟、成本 ¥0.3x） | 全程成本透明：一次完整调研约 13 分钟、三毛钱左右。每个角色花了多少钱、每一步用了多久，条形图一目了然。 |
| S10 | 4:20-4:50 | 架构一页图：七角色状态机 + artifact 交接 + 双审批点；收尾 slogan 字卡 | 研镜——每一步可查，每句引用可溯源；一杯咖啡的时间，完成一周的文献调研初稿。 |

**录制要点**
- 真实运行前先跑一遍热身（同一问题），确认稳定后再正式录；
- 审批等待期是剪辑点：录屏不停，后期加速跳过；
- 所有特写镜头（S5/S7/S9）用原速 + 鼠标逐行指点，配合解说节奏；
- DEMO 模式补拍 S3 审批打回镜头（真实模式打回会重跑花钱，DEMO 无成本）。

## 答辩预设 Q&A

- **"这不就是 Codex / 通用 Agent 吗？"** 定位不同：通用引擎追求更快更强地执行任务；研镜是科研领域工作台，创新在七角色编排、产物交接、双审批治理、引用溯源与覆盖验证。
- **"这不就是包了一层 pi SDK 吗？"** pi 提供的是单智能体执行器（等价于直接用模型 SDK）；我们构建的是 WorkflowEngine 编排、artifact 版本交接、双审批流、引用核验闭环、覆盖质量门与可观测 UI。
- **"创新点在哪？"** 四可：可观测（成本/思考全透明）、可追踪（引用级溯源）、可控（双审批+取消）、可验证（覆盖矩阵+缺口回环）。编排者是服务端代码与人类，而非黑盒嵌套。
- **"覆盖矩阵判定准吗？"** 双保险：规则预筛（词元交叠+双语锚点）+ 模型全量精判（可降级"词元撞车"假阳性），judge 失败静默回退规则；A/B 对比显示规则全绿的证据池被模型抓出 2 处降级并精确归位支撑论文。
- **"成本 ¥0.3 怎么算的？"** 每次模型调用 usage 全量落库（token/缓存/费用），DeepSeek 官方价目折算，cost-report 脚本可复现；前端总览卡实时聚合展示。
- **"效果怎么证明？"** 端到端演示 + 核验分级报告 + 覆盖矩阵 + 上表指标（均来自真实运行与 usage 落库，可复现）。
- **"用的什么模型？"** 模型无关：OpenAI 兼容接口，DeepSeek / Qwen / OpenAI 均可，用户自带 key。
- **"局限与未来？"** 当前以国际学术源为主、全文精读深度有限；未来做 PDF 精读、中英文库、自定义工作流模板与团队协作。
