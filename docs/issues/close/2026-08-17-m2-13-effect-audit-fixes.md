# M2-13 效果修复：核验可靠性 + 评估指标重设计 + 检索/下载覆盖

## 背景

M2-12 真实运行复盘（评审全文见 `docs/research/2026-08-17-m2-13-effect-audit.md`）：
工作流 completed、下载 7 成功 / 0 失败、成本 ¥1.63，但三块效果指标不达标——
引用核验 12 条仅 1 条通过（11 条 arXiv 429）、评估指标失真（命中率恒 1.00、相关度 0.10 无区分度）、
全文只覆盖 top-8（15 卡中 7 篇有全文）。

## 目标

让“可审计证据链”的叙事在演示中站得住：核验通过率显著提升、评估指标可解释且有区分度、
全文下载覆盖全部有 OA 候选的卡片；评估从规则管道升级为模型评估（evaluator 角色）。

## 问题清单（含调查）

### P0-1 引用核验实际失效（arXiv 429）

调查：`citationVerifier` 对每条引用逐篇 `lookupArxiv`（12 次请求），arXiv 限流下 11 次 429；
`arxiv.ts` 重试 3 次（6s/12s 退避）仍失败，全部标 Unverifiable。

修复方向：
1. arXiv 支持 `id_list` 批量查询（一次请求最多 10 个 ID），核验改为**先批量再逐条兜底**；
2. arXiv DOI（`10.48550/arxiv.*`）回退 Crossref lookup，避免单点依赖；
3. 核验缓存预热：检索阶段已下载/已知 DOI 的论文先入缓存。

### P0-2 评估指标失真（用户点名“很诡异”）

调查：现有评估是**确定性规则管道**（`evidence/evaluation.ts`）——主题词集取 44 个关键词并集，
命中判定“任一交集”→ 命中率恒 1.00；相关度分母为 44 → 所有卡片 ≈0.10 且均值=中位数；
大纲覆盖只比标题；19 条失败源噪音进报告。指标无区分度、不可解释，答辩时会被评委追问。

修复方向（**改为模型评估，不再用规则管道出结论**）：
1. 新增 `evaluator` 角色（writer 之后、reviewer 之前，独立会话，与其他角色一样调模型）；
2. 规则统计降级为“参考输入”：主题词集、大纲标题、引用计数、失败源清单等只作为数据喂给 evaluator，
   不再生成判定结论；
3. evaluator 按固定模板输出结构化评估报告：逐核心概念命中判定（含理由）、逐卡相关度评分（1-5 分或高/中/低）、
   逐章大纲覆盖（含“内容锚点”：章节须至少引用 1 张卡片）、覆盖不足方向与 gap 建议、总体结论（通过/打回）；
4. 报告落库 `evaluation-report.md`（模型生成 v1/v2 版本），注入 reviewer 作为审查依据。

预期效果：评估可解释（每个判定带理由）、有区分度、能发现规则管道发现不了的覆盖缺口，
并成为演示中“模型自主评估”的展示环节。

### P1-1 全文下载只覆盖 top-8

调查：`researcherStep` 只对 `slice(0, SEARCH_READ_TOP=8)` 尝试下载；303 篇 papers 无 download_status；
未尝试论文中大量带 arXiv ID / URL。根因是 M2-8 时的保守设计（串行下载慢 + 全文要进 writer prompt、
防上下文爆炸），这两个瓶颈在 M2-12（并发下载 + 摘录裁剪 + 状态落库）后已不存在，限制应取消。

修复方向：
1. **全部卡片**中有 OA 候选的论文都尝试下载（不再按 top-8 截断；保留时间预算上限防止单次流程过长，
   如最多 25 篇或 N 分钟，超出部分后台补齐）；
2. writer 执行期间后台补齐剩余下载（异步），完成后追加 `paper-fulltext.md` 新版本；
3. 无候选论文补充 OpenAlex `best_oa_location` / Unpaywall 候选。

### P1-2 检索相关度：纯引用数排名进边缘论文

调查：top-15 含“Gmail 自动回复”“RIS 优化”“审计工作流”等与主题弱相关论文，稀释相关度；
卡片 [7] 元数据损坏仍进池。

修复方向：
1. 排序加相关度因子（命中主题词数 / 引用数对数加权）；
2. 元数据异常卡片（无年份 + 作者字段损坏）过滤或标 skip；
3. 失败查询自动重试或降级（S2 无 key 时提示配置，不产生 19 条失败源噪音）。

### P2-1 Writer/Reviewer 全文摘录一致性

调查：卡片标“全文已读 7”，writer 只拿到 3 篇摘录、reviewer 拿不到全文；
草稿引言据此误写“仅 [1][2][3] 提供全文细节”，reviewer 对全文级 claims 全部 Not assessable（C3）。

修复方向：
1. 摘录区显式声明“已读 N 篇，此处注入前 M 篇，其余仅可引摘要”；
2. reviewer 材料补入关键全文摘录（或核验报告引用对应全文段），关闭 C3 类缺口。

## 范围（做）

- P0-1 核验批量 + 兜底 + 缓存预热。
- P0-2 评估改为模型评估（新增 evaluator 角色，规则统计降级为参考输入）。
- P1-1 下载覆盖扩展（全部有 OA 候选的卡片尝试 + 后台补齐，取消 top-8 截断）。
- P1-2 排序相关度因子 + 元数据过滤。
- P2-1 摘录一致性声明 + reviewer 全文摘录。

## 不做

- 六维完整评分、多审查者隔离、内容级事实核查（留 M3）。
- 引用雪球、模型精排、Reader 角色（留 M3，见评审文档第五节）。
- 评估模板从“模型生成报告”升级为“六维评分制”不做（本次只做模型评估报告，评分制留 M3）。

## 验收标准

- [ ] 真实流程核验 Unverifiable 占比显著下降（目标 ≥80% 可核验），不再成批 arXiv 429
- [ ] `evaluation-report.md` 由模型生成，每个判定带理由，能发现规则管道发现不了的覆盖缺口
- [ ] 评估报告注入 reviewer 且 reviewer 报告引用其结论
- [ ] 真实流程全文覆盖 ≥ 12/15（有 OA 候选的卡片全部尝试，不再受 top-8 截断）
- [ ] 卡片排名不再出现明显弱相关论文；元数据异常卡片被过滤或明确标注
- [ ] writer/reviewer 材料中的“已读/注入/可引摘要”声明与卡片状态一致
- [ ] typecheck / test 全绿
