# M4-1 每步质量门 + 自动迭代回环

## 背景

现状是**线性、一次到底**：规划→检索→筛选→写作→评估→审查→归纳，只在写作后做一次评估、审查时核验一次引用；
检索/筛选/写作本身**没有独立质量门**，不合格不会自动回环修正。用户要求"每步独立评估 + 迭代"：
草稿→评估→打磨→重写；检索不对→从检索开始修。

## 目标

每个步骤产出后有一个**自动质量门（自检 pass/flag）**，不合格自动触发该步回环（带评估反馈重新执行）；
若根因在上游（如检索召回不足导致筛选/写作受限），**回退到上游步骤重做**；形成迭代收敛循环。
每次迭代产物用**版本累积**（v1/v2/v3），不覆盖，与现有"卡片内版本 tab"兼容。

## 范围（做）

- 引擎增加"步骤级质量检查 + 自动回环"：步骤产出 → 质检（LLM/hybrid，明确通过/不通过 + 理由）→
  不通过则带反馈重跑该步骤；
- 质检标准按角色：检索=召回覆盖+相关性；筛选=入选相关度+剔除合理性；写作=引用有效+覆盖完整+连贯；
- 支持"回退上游"：质检判定根因在上游（如缺论文），则回退到该上游步骤重做；
- 每次回环产物版本 +1，final 默认展示最新版。

## 不做

- 无限回环（设最大迭代次数，达到则停并如实标注"未收敛"）；
- 改数据 / 模型底层。

## 验收标准

- [ ] 某步质量不达标会自动重跑该步（或上游），并最终收敛或到上限停；
- [ ] 质检有明确标准（相关性/覆盖/引用有效/连贯），输出 pass/flag + 理由；
- [ ] 每次迭代产物 v(n+1)，不覆盖，UI 版本 tab 可切；
- [ ] 达到迭代上限时如实标注"未收敛"，不静默；
- [ ] typecheck / test 全绿。
