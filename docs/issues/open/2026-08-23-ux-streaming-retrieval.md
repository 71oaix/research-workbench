# UX-3 检索与筛选流式进度展示（别让人干等）

## 背景

检索/筛选阶段用户只能看到"进行中 + 排队"，看不到"在干嘛"，干等很焦虑（图 2 检索只有状态）。
进程处理 2560 命中、204 查询、多源并发，这些过程信息没铺到界面，削弱"系统确实在干活"的信任感。

## 目标

把检索/筛选的**过程实时铺出来**：

- 正在检索的源（arXiv / Crossref / OpenAlex / S2）与状态；
- 已命中 / 去重 / 已下载篇数，随 WS 事件实时刷新；
- 筛选阶段显示"正在逐篇分析标题+摘要…已处理 N / 候选 M"。

让用户心理上感到"在工作、在筛选"，而不是白屏干等。

## 范围（做）

- 后端：检索/下载/筛选阶段通过 WS 发出进度事件（源、命中、去重、下载进度）；
- 前端：检索步骤/进度条展示实时进度；候选/筛选阶段展示处理计数。

## 不做

- 完整动作回放（留后续）；不改检索算法。

## 验收标准

- [ ] 检索阶段能看到源级进度与命中/去重计数实时刷新；
- [ ] 筛选阶段能看到候选逐篇处理进度；
- [ ] 前端在长时间检索期间始终有"正在工作"的可视反馈。
