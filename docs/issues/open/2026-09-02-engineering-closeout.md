# 工程化收尾：质量门、文档一致性与可复验交付

## 背景

全量审计确认：项目当前可以本地演示，TypeScript、构建和 239 项测试均有较好的基础；但工程化证据分散在 CI、runbook、15 个里程碑脚本和大量历史文档中，缺少一个稳定、可重复、无需外网的收尾入口。

同时发现文档有 1 个未登记文件、5 个唯一失效链接，以及 README、AGENTS、M1 架构文档的阶段描述滞后。当前根 `main` 还指向待合并 PR #39 的提交，这使“当前事实”和“可交付状态”容易被误读。

## 目标

1. 建立单一的 `npm run verify` 质量门，覆盖类型检查、构建、测试和文档完整性检查。
2. 让文档检查能稳定发现 frontmatter、INDEX、孤儿文件、幽灵条目和失效相对链接。
3. 清理当前已确认的文档漂移，并明确历史材料、正式竞赛导出物和当前架构的边界。
4. 把网络依赖的真实运行脚本与 CI 可重复验证分开，避免“脚本存在”被误读为“CI 已验证”。
5. 保持验证入口无业务副作用：测试使用临时目录隔离 PDF 等临时产物，入口前后工作区和持久化数据不发生新增或修改。

## 不做

- 不在本任务中修复 selector 补检证据池、部分输出丢论文、取消副作用等运行时正确性问题；这些应作为独立 P0 任务。
- 不在本任务中引入认证、SSRF 防护、费用预算或新的检索源。
- 不升级依赖、不引入重量级 lint/格式化体系、不改变 UI 和工作流产品语义。
- 不把真实模型、真实学术源或 Firecrawl 调用接入 CI。

## 验收标准

- `npm run verify` 在无 API key、无服务进程、无外网依赖的环境中通过。
- CI 以同一入口执行验证；失败时能区分类型检查、构建、测试和文档错误。
- 当前 docs 扫描结果为：无 frontmatter 缺失、无非法状态、无孤儿、无幽灵、无失效链接。
- README、AGENTS、当前架构文档和 INDEX 对项目阶段、已合并任务、开放任务和正式导出物的描述一致。
- 现有真实运行/评测脚本继续保留，但明确为手动或联网验证，不被误认为 CI 质量门。
- 验证入口及其测试临时目录不写入仓库内数据库、PDF、artifact 或报告文件；临时产物退出时清理。
