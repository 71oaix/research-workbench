# 证据可得性门槛 + 评估迭代闭环 + 官方文档补位

## 背景

热身二（窄题"多智能体记忆管理"）暴露四个真实问题：

1. **覆盖矩阵两列重复**：covered 行的"缺口建议/相关推荐"列直接复制支撑论文列（coverage.ts 渲染缺陷）；
2. **产物版本空转**：打回 planner 后下游全部重跑（行为正确），但重跑结果实质未变时也照样升版本号，产生"看起来一模一样的 v2"；
3. **证据可得性无门槛**：无摘要（abstract 为空）的候选照样入选证据池，下载失败的也只标记不拦截——evaluator 抓出"2/12 连摘要都没有、8/12 无全文"，相关性定级与引用核验都建立在空证据上；
4. **评估后无迭代**：evaluator 给出低分与逐条批评（完整性 2 分："草稿以空白声明代替回答"），但流程照样走完标"完成"——批评意见落在报告里，没有任何机制驱动重写或补检索。M4-1 当初收窄掉了"评估→写作"回环，只剩"检索↔覆盖"回环。

其中 3、4 是"称不上好用"的核心：**透明有了，处置没有**——会体检不会治病。

## 目标

- 证据池只收"可核验"的证据：摘要可得是入选硬条件，下载失败有限重试；
- 评估低分自动触发一轮带反馈的重写，收敛或如实标注"未收敛"；
- 工程实践类子问题（学术文献天然稀疏）给出官方文档补位路径；
- 版本号回归"实质变化"语义，消除空转版本。

## 范围（做 / 不做）

**A 组（证据质量，必修）**
- 覆盖矩阵 covered 行建议列显示"—"（不再复制支撑论文）
- 产物 persist 前与最新版做内容比较，相同则不升版本
- selector 入选门槛：摘要与全文均不可得的候选不入证据池（保留在候选池与报告中，注明"仅题录"）；下载失败给 1 次带超时的补偿重试（复用 Unpaywall 候选链路）

**B 组（评估迭代闭环，推荐）**
- evaluator 完成后，若综合分 < 3.5 或完整性 < 3：引擎自动带"评估报告中的批评要点"作为 feedback 打回 writer 重写一次（复用现有打回反馈机制）；二评后仍不达标则如实标注"未收敛"并完成
- 全程次数上限 1 次，防止回环失控

**C 组（官方文档补位，两档选一）**
- 轻量版：覆盖矩阵对"框架实践/工程对比"类子问题的缺口建议中，附官方文档白名单链接（硬编码已知框架文档地址，无抓取、无新源），标注"学术文献对此类问题覆盖稀疏，建议结合官方文档"
- 完整版：白名单域的文档抓取入证据池（新证据类型 official-docs，独立分组编号）——工作量 2-3 小时，演示稳定性风险中等

**不做**：通用 web 搜索接入（噪音与 key 问题）、多轮评估回环（上限 1 次）、向量检索（仍延后）。

## 验收标准

- [ ] 覆盖矩阵 covered 行建议列为"—"，不再重复
- [ ] 重跑结果不变时产物版本号不变；有实质变化才 +1
- [ ] 无摘要候选不入证据池（报告中可查"仅题录"名单）；下载失败重试 1 次后仍失败则标注
- [ ] 评估低分触发自动重写一次；二评仍低时工作流完成但标注"未收敛"
- [ ] typecheck / test 全绿；真实运行一轮验证窄题分数改善
