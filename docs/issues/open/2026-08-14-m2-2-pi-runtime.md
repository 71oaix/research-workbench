# M2-2 角色运行时接入 pi SDK

## 背景

M2-1 的 WorkflowEngine 已能跑通状态机、artifact 交接和审批点，但执行器是 FakeStepRunner。M2-2 把它换成真实运行时：用 pi SDK 接入 opencode-go 的 `deepseek-v4-flash`，让 Planner 角色真实生成检索计划，验证“研究问题 → 计划 → 审批”的第一段真链路，并为后续 Researcher / Writer / Reviewer 铺路。

## 目标

- `PiRuntimeProvider`：按角色创建 pi SDK 运行时（角色专属 system prompt），默认模型 `opencode-go/deepseek-v4-flash`，支持每角色覆盖
- `PiStepRunner`：替换 FakeStepRunner，组装角色 prompt + 输入 artifact 摘要，调用真实模型，输出写入 artifact
- 用量落库：pi 事件流中的 token / 成本写入 `usage_records` 并广播
- 失败可观测：runner 异常时工作流进入 `failed` 状态，不卡死在 running
- 无 key 时接口返回明确错误（503 + 提示），不崩溃

## 范围（做）

- `apps/server` 安装 `@earendil-works/pi-coding-agent@^0.80.3`
- 配置：`OPENCODE_GO_API_KEY`、`PI_DEFAULT_MODEL`（默认 `opencode-go/deepseek-v4-flash`）、`PI_MODEL_PLANNER/RESEARCHER/WRITER/REVIEWER`（可选覆盖，未设置回退默认）
- `src/runtime/piConfig.ts`：环境变量解析与校验
- `PiRuntimeProvider`：创建 / 复用角色运行时，`send` / `close`
- `PiStepRunner`：prompt 组装（角色提示词 + 输入 artifact 摘要）→ 调用 → artifact 内容
- `shared` + engine：`WorkflowStatus` / `StepStatus` 增加 `failed`，runner 异常置 failed 并广播
- 文档：runbook 配置说明、架构更新

## 不做（明确排除）

- 学术检索工具（M2-3）
- Writer / Reviewer 语义完善（M2-4）
- 前端工作流 UI（M2-5）
- 预算上限、重试、超时、并发（M3）
- WS 真实通道（M2-5）

## 验收标准

- [ ] 默认模型解析为 `opencode-go/deepseek-v4-flash`；`PI_MODEL_*` 覆盖生效；非法模型名返回配置错误
- [ ] 真实调用：四步工作流 start 后，Planner 真实调用 deepseek-v4-flash，产出含“子问题 / 关键词 / 大纲”的 `01-plan.md`，然后停在审批点
- [ ] 每次模型调用后 `usage_records` 有记录（tokens + cost），并广播 `usage.recorded`
- [ ] 未配置 API key 时接口返回 503 与明确提示；runner 异常时 workflow / step 置 `failed`
- [ ] `npm run typecheck` / `npm test` 全绿；runbook 可照做
