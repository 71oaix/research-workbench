# M2-15 模糊问题澄清 + 标题摘要筛选 + 下载候选增强

## 背景

M2-14 真实运行：召回 1113/797（目标达成），但 top-15 混入“太极统一场论”“谣言传播”“大学英语教学”
等无关论文，评估/审查因此打回。根因是两层的策略问题：

1. **问题拆解**：宽泛问题（如“研究下什么是 agent”）直接抓关键词开搜，缺少先和用户澄清锚定点的环节；
2. **筛选方法论**：论文的标题与摘要是判断是否下载/入池的第一依据，当前是“全量下载 + 引用数/主题词加权”，
   没有“批量深入分析标题摘要（内容/场景/创新点）”的筛选环节。

## 本轮已修复的明显 bug（背景记录）

- **近重复合并增强**：同一论文中英文双标题/格式漂移（M2-14 的 [6]/[7] 太极论文）未合并；
  现按“标题 Jaccard ≥0.75 或中文 bigram ≥0.7 + 首作者或年份一致”合并。
- **证据状态一致性**：草稿“全文/仅摘要”声明与卡片状态矛盾（[11][14] 全文已读却被写仅摘要、
  [5] 下载失败被遗漏）；现由机器从卡片生成“证据状态清单”强制 writer 照抄，
  证据池模型（`EvidencePoolCard`）补齐 `downloadStatus / downloadError` 字段。

## 目标

让宽泛问题先澄清再检索，让入选证据池的论文都经过“标题 + 摘要”的深入筛选，
从根上解决“召回高但精度低”。

## 问题清单

### P0-1 规划澄清：宽泛问题主动提问（用户方法论核心）

现状：planner 直接按“检索关键词/锚定点”模板输出，模糊问题（无领域/场景/实体锚点）不提问。

方案：
1. planner 检测模糊问题（锚点过少/过于宽泛的判定规则，或由模型自行判断）时，
   在 plan 中输出“## 澄清请求”小节（列出 2-4 个澄清问题，如：什么类型的 agent？单/多智能体？
   应用场景？时间范围？），并在该 plan 上标记“待澄清”提示；
2. 复用现有审批机制：用户通过审批意见回答澄清问题，planner 重跑时吸收回答并收敛锚定点；
3. UI 审批面板：检测到 plan 含“澄清请求”时显示提示条“该计划需要澄清，请在意见中回答以下问题”。

### P0-2 标题摘要筛选：模型批量分析候选池

现状：检索 → 全量下载 → 卡片，无“先筛后下”。

方案：
1. researcher 阶段拆分：确定性检索产出“检索候选池”（30-50 篇，含标题 + 摘要，摘要缺失的补抓或剔除），
   不立即下载全文；
2. 新增 `selector` 角色（researcher 之后、writer 之前）：批量深入分析每篇候选的标题与摘要，
   从“内容、场景、创新点是否符合研究问题”逐篇给出 入选/剔除 + 理由，输出 `research-cards.md`
   并触发入选论文的全文下载；
3. 规则预筛保留为第一层（主题词命中过滤），模型筛选作为第二层判断。

### P1-1 下载候选增强

- 对只有 1 个 PDF 候选的论文补 Unpaywall（`SEARCH_UNPAYWALL_EMAIL` 可配），降低 M2-14 的 3/9 失败率。

## 范围（做）

- P0-1 规划澄清（planner 澄清请求 + 审批面板提示 + 意见吸收）。
- P0-2 selector 角色 + 候选池拆分 + 标题摘要批量筛选。
- P1-1 Unpaywall 下载候选。

## 不做

- 模型精排、引用雪球、Reader 角色、六维评分（留 M3）。

## 验收标准

- [ ] 宽泛问题（如“研究下什么是 agent”）运行后 plan 含“澄清请求”，用户意见回答后第二轮锚点明显收敛
- [ ] 真实运行候选池 30-50 篇，入选 top-15 无“太极统一场论”类明显无关论文
- [ ] 每张入选卡片附筛选理由；相关度中位数较 M2-14 提升
- [ ] 单候选论文下载失败率下降（Unpaywall 生效）
- [ ] typecheck / test 全绿
