# M2-7 检索迭代与证据版本闭环

## 背景：一次真实运行的自评

2026-08-15 用研镜完整跑了一次真实任务「研究下多智能体的记忆架构」，并走了一次「打回修改」：

- 计划（01-plan.md v1）：质量好，给出 7 组检索关键词与完整大纲；
- 检索 v1：63 条命中、58 篇去重，Semantic Scholar 一组失败，OpenAlex 兜底；
- 用户打回：「感觉你找的论文太少了，而且引用数也很低，参考价值不够」；
- 检索 v2：13 条命中、8 篇去重，Semantic Scholar 三组全部失败，OpenAlex 返回大量无关论文（心理健康、无人机、绿色 AI、谣言、意识计算、中文纠错等），模型如实报告“补偿检索失败”；
- 写作：模型自发改用 `[V1-x]` / `[V2-x]` 前缀编号引用，把 v1 的 15 篇与 v2 的 3 篇混编进综述；
- 审查：自动引用检查按纯数字 `[n]` 匹配，报告“引用次数 0”，自动审查完全失效；Reviewer 靠人工识别出三个阻断级问题（引用格式不兼容、v1 证据不在当前证据池、覆盖度缺口大），结论“不通过”，并给出修复建议。

## 自评结论

1. **打回重跑没有“变聪明”**：同一批关键词、同一参数重跑，结果不升反降。根因是检索管道缺少补偿能力：计划给了 7 组关键词但只用了前 3 组；每查询 25 条固定；没有引用数下限过滤；没有引用雪球。
2. **数据源可靠性不足**：Semantic Scholar 无 key 限流导致整组失败，双源退化为单源；OpenAlex 对中文混合关键词相关性差，且没有自动补英文等价查询。
3. **证据版本错位**：打回 researcher 后，writer 只看到最新版 research-cards（v2），但草稿引用了 v1 的论文。证据池应该是“合并去重后的全集”，而不是“最新版本替换旧版本”。
4. **引用格式与自动检查脱节**：writer 使用 `[V1-x]`，lint 只认 `[n]`，导致自动审查形同虚设。需要 prompt 强约束 + lint 宽容解析（前缀编号映射 / 格式异常提示）。
5. **Reviewer 环节本身有效**：准确指出了格式、版本、覆盖度、借位引用问题，说明评审设计可用，问题在上游检索与证据管理。
6. **流程闭环不顺**：Reviewer 报告“不通过”，用户仍需手动把审查意见复制到下一次打回；产品应提供“一键打回 Writer 并附带审查意见”。

## 目标

- 打回检索后，结果数量与相关度不劣于上一版（用足关键词组、按需提高每查询条数、支持引用数下限过滤）
- Semantic Scholar 失败可见并可缓解（记录失败源、提示配置 key、中文查询补英文等价查询）
- 证据池按“合并去重 + 版本来源标注”提供给 Writer / Reviewer，引用必须落在合并池内
- 引用格式强约束 + lint 兼容 `[V1-n]` 并给出格式异常提示，自动审查不再失效
- Reviewer 不通过时，前端一键“打回 Writer 并附带审查意见”

## 范围（做）

- 关键词提取：用足计划中的关键词组（当前上限 3 组），支持中英文拆分与组内多查询
- 检索补偿：打回意见触发确定性补偿（提高 per-query、按引用数下限过滤、补用未使用过的关键词组）
- 数据源：S2 失败统计与 key 提示；中文查询自动补英文等价查询（用计划中已有的英文关键词或简单规则）
- 证据池：research-cards 多版本合并为当前证据池（按 dedup key 去重，标注来源版本），writer / reviewer / lint 统一基于合并池
- 引用检查：prompt 强制纯数字 `[n]`；lint 兼容 `[V1-n]` / `[V2-n]` 映射；0 引用但草稿含引用符号时标记“格式异常”
- 前端：Reviewer 不通过时提供“打回 Writer 并附带审查意见”的一键操作

## 不做

- 引用雪球 / 模型精排 / 向量检索（仍留 M3）
- 对话式记忆管理
- UI 视觉打磨

## 验收标准

- [ ] 打回 researcher 后使用全部关键词组，结果数量与相关度不劣于上一版
- [ ] S2 失败时明确记录并提示配置 key；中文关键词自动补英文查询
- [ ] writer 引用编号全部落在合并证据池内，lint 引用数 > 0
- [ ] lint 兼容 `[V1-n]` 并给出格式异常提示
- [ ] reviewer 不通过时前端一键“打回 Writer 并带审查意见”
- [ ] typecheck / test 全绿，verify 脚本更新
