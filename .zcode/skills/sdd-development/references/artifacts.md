# 产物硬性要求

> 目标：**用户即使不写一行代码、不看一个代码文件，也能对关键逻辑和流程有清晰准确的认知。**

## plan 必须包含

- **任务解释**：一句话说清解决什么问题、为什么值得做
- **关键决策**：方案选择与权衡——做了什么选择、放弃了什么、为什么（决策即上下文）
- 实现步骤拆分
- 测试方案（如何验证）
- 本次需要同步更新的文档清单

## 涉及 UI 的 plan 必须提供

- 设计图（线框图/截图）**或** HTML 交互预览（可运行的最小页面）

## 代码合并（步骤⑧）必须提供

- **关键改动说明**：改了什么、为什么、影响哪些模块
- **项目预览地址**：本地可运行地址（如 `http://localhost:5173`）或部署预览链接
- 用户据此验收，不看代码

## 为什么（博客原文）

> 所有的 plan 都要提供任务解释和关键决策等信息；
> 所有涉及 ui 的 plan 都提供设计图或者 html 交互预览；
> 所有代码合并都提供关键改动说明，并提供项目的预览地址。
> 以此做到即使不写一行代码，也对项目的所有关键逻辑和流程都有清晰和准确的认知。
> **确保做决策的人对这件事有足够的认知，才能做出正确的决策。**
