# 文档状态流转表

> 文档只有两个状态：active（启用）和 archived（已归档）。
> 独立开发者不需要「讨论阶段」或「稳定阶段」——想到就做，不用就归档。

## 状态总览

| 状态 | 含义 | 特点 |
|------|------|------|
| active | 当前启用、有效的文档 | 内容最新，可直接引用 |
| archived | 不再使用的归档文档 | 保留内容不删除，可追溯可恢复 |

## 状态图

```
         ┌──────────┐
   创建  │  active  │   归档（不再使用/被替代/过期）
  ─────→ │ （启用） │  ──────────────────────────────→  ┌───────────┐
         │          │                                     │ archived  │
         └──────────┘  ←──────────────────────────────   │（已归档） │
                        恢复（reactivate）                └───────────┘
```

## 流转规则

| 流转 | 触发条件 | AI 自动执行？ |
|------|---------|-------------|
| _创建 → active | 用户说「写个文档」「记录一下」 | ✅ 自动设为 active |
| active → archived | 文档不再使用、被新文档替代、内容过期 | ❌ 需要用户确认或 docs-scan 建议 |
| archived → active | 用户说「恢复了」「重新启用」 | ✅ 自动恢复 |

## 归档条件

满足以下任一条件时，可考虑归档：

1. **被替代**：有新文档取代了它的职能
2. **过期**：内容与当前项目状态不再匹配
3. **放弃**：这个方向不再继续
4. **废弃**：用户明确说「不用了」

## 归档规范

```
1. 设置 status: archived
2. 如果有替代文档，填写 supersedes: <替代文档路径>
3. 更新 updated 字段为今天
4. 更新 INDEX.md
```

## 恢复规范

```
1. 设置 status: active
2. 清除 supersedes（如果之前有填）
3. 更新 updated 字段为今天
4. 更新 INDEX.md
```

## 判断文档状态的流程

```
① read(path, offset: 1, limit: 5)  → 读取 frontmatter
  ↓
② 检查 status 字段
  ├─ active → 直接引用，内容为当前有效
  └─ archived → 查看 supersedes：
       ├─ 有 supersedes → 告诉用户"该文档已归档，被 xx 替代"
       └─ 无 supersedes → 告诉用户"该文档已归档，内容仅供参考"
```

## 注意事项

- **不删除文档**：归档保留历史，删除造成信息丢失（参见 gotchas G005）
- **替代关系**：归档时尽量填写 supersedes，保持知识网络完整
- **恢复自由**：归档文档随时可以恢复为 active，没有次数或时间限制
