# Gotchas

> 本文件记录使用 doc-contract skill 时常见的错误和踩过的坑。

## Gotcha 记录

### G001：用户讨论想法 vs 明确要做，区分不清晰

- **默认假设：** 只要用户提了跟文档相关的内容就自动创建文档。
- **实际规则：** 用户仅讨论想法（"想一下""你觉得xxx怎么样"）时，不写文档。只有用户表达明确要做的意图（"加一个""改成""试试看"）时才创建。
- **正确做法：** 先问用户"要不要记成文档"，用户确认后再创建。

### G002：创建文档后容易忘记更新 INDEX.md

- **默认假设：** 创建好文档就完成了。
- **实际规则：** 只要动了文档（创建、修改、移动、归档），都必须顺手更新 `docs/INDEX.md`。
- **正确做法：** 把"更新 INDEX.md"作为文档操作的最后一步固定下来。

### G004：Archived 文档缺少 supersedes 指向

- **默认假设：** 把文档标为 archived 就够了。
- **实际规则：** 如果是因为被新文档替代而归档，必须在 archived 文档的 frontmatter 中填写 `supersedes` 字段，指向替代文档。
- **正确做法：** 归档时检查是否有替代文档，有则填写 supersedes，无则不填。

### G005：归档不是删除

- **默认假设：** 用户说「把这篇删了」就物理删除文件。
- **实际规则：** 文档应该归档（status: archived）而非删除。归档保留内容可追溯，删除造成信息丢失。
- **正确做法：** 向用户解释归档的好处（保留历史、可恢复），如果用户执意要删，再用 git rm。
